## 目标

本轮修改目标是先解决影响交付、离线运行和长期维护的高优先级问题，再逐步降低 `Pipeline`、`KillDetector` 和配置系统的复杂度。执行顺序遵循“先阻断、再稳定、后重构”的原则。

## 总体优先级

| 优先级 | 范围 | 目标 |
| --- | --- | --- |
| P0 | 仓库交付完整性 | 修复 `src/history` 被 `.gitignore` 忽略的问题，保证干净 clone 可运行。 |
| P1 | 离线合规与工程边界 | 移除运行时 CDN 依赖，补仓库完整性测试，减少最明显的架构漂移。 |
| P2 | 核心架构拆分 | 拆分 `Pipeline` 与 `KillDetector`，减少重复逻辑和重型信号重复计算。 |
| P3 | 工程治理 | 引入 lint/type/schema/依赖治理，让后续迭代更可控。 |

## 阶段 4：KillDetector 拆分与规则计算优化

预计耗时：3-5 天  
目标：降低检测逻辑复杂度，避免规则模式重复执行 OCR/模板等重型信号。

### 任务 4.1：定义信号结果数据结构

新增文件建议：

```text
src/ai/signals.py
```

建议结构：

```python
from dataclasses import dataclass, field
from typing import Dict, Any

@dataclass
class SignalResult:
    ocr: float = 0.0
    template: float = 0.0
    color: float = 0.0
    yolo: float = 0.0
    details: Dict[str, Any] = field(default_factory=dict)

    def as_dict(self) -> Dict[str, float]:
        return {
            "ocr": self.ocr,
            "template": self.template,
            "color": self.color,
            "yolo": self.yolo,
        }
```

验收标准：

- 原有 event 输出中的 `signals` 字段保持兼容 dict。
- 现有测试不需要大范围重写。

### 任务 4.3：避免规则模式重复计算重型信号

现状：

- `_precise_detect()` 已经计算一次信号。
- `_evaluate_rules()` 在规则模式下可能再次 `_compute_rule_signals()`。

目标：

- 默认全局规则使用已计算信号。
- 只有存在 `detection_overrides` 且影响信号计算时，才计算 per-rule signal。
- 对 per-rule effective config 增加短期缓存。

验收标准：

- 规则测试保持通过。
- 增加一个 mock OCR/模板调用次数测试，确认单规则无 override 时不会重复调用 OCR。

## 阶段 5：配置系统强化

预计耗时：2-4 天  
目标：减少配置歧义和运行期隐性失败。

### 任务 5.1：统一 batch size 配置

问题：

- `config/default_config.yaml` 中有 `detection.batch_size`。
- `Pipeline` 中读取的是 `ai.batch_size`，默认 fallback 为 16。

修改方案：

- 明确统一为：

```yaml
ai:
  batch_size: 16

detection:
  chunk_size: 256
```

- 或统一放在 `detection` 下，但必须保证代码和文档一致。

建议优先方案：

- YOLO batch size 属于 AI 推理层，放 `ai.batch_size`。
- 检测帧 chunk 属于 detection pipeline，放 `detection.chunk_size`。

验收标准：

```powershell
.venv\Scripts\python.exe -m pytest tests/test_config.py tests/test_pipeline.py -q
```

### 任务 5.2：补充配置校验

扩展 `src/config/config_loader.py` 校验：

- ROI 必须为 4 个数值，范围为 0.0-1.0，宽高大于 0。
- HSV lower/upper 长度为 3，H/S/V 范围合法。
- `highlights.pre_kill_time`、`post_kill_time` 非负。
- `highlights.game_volume`、`music_volume` 在 0.0-1.0。
- `video.frame_extraction_mode` 只能为 `bulk` 或 `precise`。
- `detection.weights` 建议允许不强制总和为 1，但要全为非负且至少一个正值。

## 风险控制

- 不在同一 PR 中同时做大重构和行为变更。
- `Pipeline` 拆分时保持外部接口兼容。
- `KillDetector` 拆分时保持 event JSON 字段兼容。
- CDN 本地化时先保证功能不退化，再考虑视觉细节。
- 配置校验增强可能暴露旧配置问题，应先对现有 `config/games/*.yaml` 跑校验并补迁移说明。
